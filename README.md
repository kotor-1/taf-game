# 放課後トラック部

新設された高校の陸上部を育てる、オリジナルのドット絵ブラウザーゲームです。1年生の男子6名・女子6名から始まり、選手別の月間育成方針、毎週の練習、施設投資、秋の中学生スカウトを組み合わせてインターハイを目指します。

**ブラウザーで遊ぶ：[放課後トラック部](https://kotor-1.github.io/taf-game/)**

PC・スマートフォンに対応。インストールやログインは不要です。

## はじめて遊ぶとき

画面の「チュートリアルを始める」から、7段階の監督ガイドを使えます。選手の能力確認、月間育成、練習カード、1週間の進行、大会日程、部の歴史と目標、セーブを、実際の画面で順番に案内します。4月1週には、週を進める前に年度目標や大会モードも選べます。

途中で中断したり、「説明だけで次へ」で操作をスキップしたりできます。「遊び方」（スマートフォンは左下の「？」）から、続きの再開・最初からの再実行ができます。今の部活やセーブはリセットしません。時間が進む操作は自分で選び、ガイドの進捗はゲームのセーブとは別に、このブラウザーへ保存します。

## 起動

Node.js 18 以降を使用します。ゲーム用の追加パッケージは不要です。

- macOS: `launch.command` をダブルクリックすると、サーバーを起動してブラウザーを開きます。
- ターミナル: このフォルダーで `npm start` を実行し、`http://127.0.0.1:4173` を開きます。終了は `Ctrl+C`。
- ポートを変更する場合: `PORT=4174 npm start`。

## 育成とチーム編成

月の初めに、選手ごとに伸ばしたい能力を選び、月間方針を確定します。スピード・持久力・パワー・技術・敏捷性・柔軟性・精神力の7能力の組み合わせから種目適性を比較し、得意種目を伸ばすか弱点を補うかを考えましょう。週ごとの練習カードと練習強度、体力回復、施設の効果も成長に影響します。大会前は疲労とケガに注意してください。

通常の学校大会は男女別です。100m・400m・1500m・走幅跳・走高跳・棒高跳・三段跳・4×100mリレーに加え、男子110mハードル・女子100mハードルを実施します。1大会で個人種目は1人1種目まで、リレーとは兼任できます。リレーは同性の異なる4名を1～4走へ配置し、走順・バトン技術・個人種目との兼任による疲労を考えて編成します。

大会のエントリー画面で、出場資格と予想記録を確認できます。U20・U18の選手権は年齢区分と参加標準記録があり、通常の学校大会とは出場条件が異なります。年齢は生年月日から、その大会が開かれる暦年末の年齢で判定します。屋外選手権の参加標準はゲーム独自の設定です。出場できる選手がいない大会は見送れます。同じ週のU20とU18は順に処理し、両大会を終えてから次の週へ進みます。

v2.4では高校の大会に合わせて記録の計算と相手の実力分布を調整しました。通常モードの地区100mは、男子11.40秒・女子13.20秒前後が県大会進出の目安です。固定の参加標準ではなく、その大会の総合順位で進出を判定します。育成・体力・作戦が記録に影響し、強豪校チャレンジでは目安も高くなります。既存選手の能力と過去の記録は保持し、更新後の予想記録・大会から新しい計算を使います。

| 大会 | 個人トラック（人数／校数） | 跳躍（人数／校数） | リレー（チーム／校数） | 次大会へ進出 |
| --- | --- | --- | --- | --- |
| 地区・新人地区 | 48人／24校 | 24人／16校 | 24／24校 | 個人トラック16位、跳躍・リレー8位以内 |
| 県・新人県 | 64人／40校 | 32人／24校 | 32／32校 | 6位以内 |
| 地方・新人地方 | 48人／36校 | 32人／24校 | 24／24校 | インターハイ地方大会のみ6位以内 |
| インターハイ | 64人／56校 | 40人／32校 | 48／48校 | — |

人数は男女・種目別で、自校の1枠を含みます。屋外U18・U20選手権はトラック48人・40校、跳躍24人・20校。室内はトラック32人・28校、跳躍8人・8校です。ライバルには個人名と学校名があり、同じ学校から複数選手も出場します。メダルは3位以内で、次大会進出とは別です。同記録は同順位とし、進出枠の境界では同順位の選手全員が通過します。

大会のラウンドはゲーム向けにまとめて総合記録で判定し、結果画面から全員の順位を見られます。映像は自校を含む最大8人の抜粋です。出場規模・進出枠はゲーム独自の設定で、特定地域の実大会を完全再現するものではありません。

大会の2〜3週前には、出場予定の選手の体力を整えましょう。「堅実に」は安定重視、「勝負をかける」は記録の振れ幅も大きくなる作戦です。全国で優勝を狙うときは、育成だけでなく大会前の休養と作戦選択も大切です。

10月には中学生をスカウトできます。勧誘に成功した選手は翌年4月の入学予定者になり、その場で高校の大会に出場することはありません。年度末には進級・卒業があり、翌4月に新1年生の男子6名・女子6名が入部します。スカウトした選手もその新入部員に含まれます。3学年を育て、世代交代しながら部を強くしていきましょう。

## 毎年の挑戦と、部の歴史

「部の歴史と目標」で、毎年4月1週に年度目標と大会モードを選べます。目標は公認自己ベスト20回、6つの男女・種目区分で入賞、男女リレー入賞、インターハイ正式出場、インターハイ優勝、室内選手権入賞の6種類。達成すると部費の支援を1年度に1度受け取れます。週を進めると年度内の目標とモードが固定されます。

通常モードに加え、「強豪校チャレンジ」では相手の実力が地区・県・地方で4、全国で8高くなります。育成効果は通常と同じで、自チームの能力への直接補正はありません。今の部員・施設・セーブのまま挑戦でき、翌年4月1週にモードを選び直せます。

学校記録は男女・種目・ハードルの高さごとに保存し、記録保持者が卒業しても残ります。卒業生名鑑には直近60人の能力と自己記録を、年度の歩みには直近30年の成績を残します。累計の目標達成数・インターハイ優勝年度・最高連覇・卒業人数も確認できます。大会の詳細は直近60大会、活動日誌は直近100件に制限して、プレイ年数に比例してセーブが肥大化しないようにしています。

既存のv2セーブも続けられます。新しい記録機能は残っている大会履歴を引き継ぎますが、既に保存されていない過去の大会や卒業生は復元しません。年度目標や卒業生名鑑は更新後から蓄積します。

人数が増えたときは、月間育成画面の「適性から育成案を作る」で、得意種目と能力の伸びしろを参考に全員の重点能力を一括設定できます。設定後に一人ずつ調整できます。個人メニューも「得意種目にメニューを合わせる」で適性・体力に合わせて設定できます。

## 保存

進行状況は各操作のあとにブラウザーへ自動保存します。ゲストのままでも遊べます。画面上部の「ログイン・登録」からIDとパスワードを作成すると、Supabaseのクラウド保存を使い、別の端末でも同じIDで続きを遊べます。保存状況と保存時刻を表示し、設定から手動保存、JSONファイルの書き出し・読み込みもできます。

IDは半角英数字・`_`の4〜20文字（大文字と小文字を区別しません）、パスワードは8文字以上です。メールアドレスの入力・確認はありません。忘れた場合は主催者 **rkoto2810@gmail.com** にお問い合わせください。主催者が本人確認後にパスワードを再設定します。ログイン後のアカウント画面に、問い合わせ用の番号とパスワード変更の操作があります。

最初のログインでは、ゲストの部活を引き継ぐか、新しい部活を始めるかを選べます。既にクラウド保存があるIDではその部活を読み込みます。ゲストと各アカウントの端末内保存は別々に保持し、ログアウトすると元のゲストの部活に戻ります。

端末内ではセーブを圧縮し、長年の大会結果による容量の増大を抑えます。旧形式はそのまま読み込め、書き出しファイルとクラウド保存は通常のJSONです。変更前のデータを1世代バックアップし、保存データが破損している場合は有効なバックアップから復旧します。複数タブで同時に遊んだときは、古いタブが新しい進行を上書きしないよう保護します。保存できない場合は画面に表示されます。その場合もファイルへの書き出しを利用できます。

クラウドへの保存は、最後に確認した更新番号を照合して行います。複数端末で違う進行になった場合は自動で上書きせず、続けるセーブを選びます。通信が途切れても端末内保存を保持し、接続後に再試行できます。クラウド保存済みの表示を確認してから端末を切り替えてください。

ログインを使わずに別の端末へ移る場合や、`localhost` のローカル版から公開版へ移る場合は、元の画面で「設定 → 書き出す」を選び、移行先で「設定 → 読み込む」を選んでも引き継げます。プライベートブラウズの終了やブラウザーデータの削除に備え、大切な進行はファイルでも保管してください。

この版は新設校・男女別・48週制への変更に伴い、v2専用の保存領域を使用します。旧v1データは自動変換せず、旧保存領域に残します。v1をv2として読み込むことはできません。ブラウザーのデータを削除すると保存も消えるため、必要に応じて書き出して保管してください。

## 開発・確認

- `npm run dev`: ローカルサーバーを起動します。
- `npm run build`: 公開用の静的ファイルを `docs/` に生成します。ゲームに必要なファイルだけを含み、更新時のキャッシュを避けるため各アセットのURLに内容のハッシュを付与します。
- `npm test`: 月間育成、男女別出場、年間日程、室内種目、スカウト、世代交代、保存検証などのロジックテストを実行します。
- `npm run test:browser`: サーバー起動中に、デスクトップ・スマートフォンの操作と表示を確認します。開発用にPlaywrightとChromiumが必要です。`PLAYWRIGHT_MODULE_PATH`で既存のPlaywright、`GAME_URL`で対象URL、`QA_OUTPUT_DIR`でスクリーンショットの出力先を指定できます。
- `npm run test:career`: 年度目標・モード選択、世代交代後の記録・名鑑・年度成績、旧v2セーブの継続をPC・スマホ画面で確認します。
- `npm run test:tutorial`: PC・スマホでガイド全7段階、中断・再開・スキップ、既存セーブの保護、保存失敗時の表示、キーボード操作を確認します。
- `npm run test:fields`: 大人数大会の順位表、進出とメダルの区別、下位選手のハイライト、旧8人大会の履歴、保存の往復をPC・スマホで確認します。
- `npm run test:storage`: `TAF_LONG_SAVE_FILE`に長期プレイのセーブJSONを指定し、複数の保存枠・バックアップ・復元を実ブラウザーで確認します。`TAF_AUTH_QA_FILE`も指定するとクラウドへの移行と別端末での再開を検証します。
- `npm run test:auth`: 専用の検証アカウントでログイン・クラウド同期を確認します。認証情報はリポジトリに保存せず、テスト専用ファイルを`TAF_AUTH_QA_FILE`で指定します。

外部画像・外部フォントは不要です。Supabaseの公式SDKを固定バージョンで同梱しています。ログインの認証情報とログイン中のゲームセーブは、設定済みのSupabaseプロジェクトへ送信します。ゲストのゲームセーブはクラウドへ送りません。既存ゲームのキャラクターや画像素材は使用していません。

Supabaseの初期設定、保存テーブル・アクセス制限、主催者によるパスワード再設定は [supabase/SETUP.md](supabase/SETUP.md) を参照してください。管理用キーやパスワードは公開ファイルに含めません。

## 長期プレイの検証（v2.4）

3つの育成方針で各128年、合計384年・18,432週・4,224大会を自動プレイしました。入学・進級・卒業・スカウト・室内大会・目標達成・通常/強豪モードを組み合わせ、各年度と大会後にセーブの妥当性とJSON往復を確認しています。10,000年から10,001年へ進む境界、旧来の累計値上限を超えた保存も検証済みです。

大会の人数を増やしたv2.4でも、同じ384年の試験を再実行しました。自然に育てた129年目の約5.4MBのセーブで、PC/スマホの表示と操作、学校記録・卒業生名鑑、過去大会の再生、書き出し、クラウド移行、別端末の再開を確認済みです。ゲスト・2アカウント・各バックアップの6枠は圧縮後合計約196万文字で、60大会分の全順位を保持しています。大容量の転送に対応するため、クラウド保存・読込は60秒、認証関連は15秒の通信期限を設けています。

別途、通常モードで大会前3週の休養と全国大会での「勝負をかける」を組み合わせ、3つの開始seed・合計31年を試しました。能力・資金・設備を直接変更せず、いずれも創部3年目に全国優勝へ到達しています。

試験は代表的な戦略・Chromium環境によるものです。すべての端末・操作・通信障害で無故障を保証するものではありません。終了年はゲーム上の目標として設けていませんが、数値の安全整数限界では破損を避けるため進行を止めます。確認コマンド・条件は上記の開発手順と各テストに残しています。

## GitHub Pages への公開

リポジトリは [kotor-1/taf-game](https://github.com/kotor-1/taf-game) です。GitHub Pages は **Deploy from a branch → main → /docs** を使用します。カスタム GitHub Actions のアカウント制限に依存せず、標準の Pages 公開処理で配信します。

更新時は `npm test` と必要なブラウザーテストを実行し、`npm run build` で `docs/` を再生成してください。ソースと `docs/` の変更をコミットして `main` へ push すると、自動で公開されます。`docs/` は生成物なので、直接編集せず元のファイルを修正します。

更新しても保存キーは変更しないため、公開URLで保存済みのゲームを続けられます。ゲームの保存データをリポジトリへアップロードする必要はありません。
